# Generate NuGet packages from Visual Studio builds

## Summary

Visual Studio builds now generate complete multi-target NuGet packages for all packable projects in Canary, Nightly, and Release configurations, including Lite variants.

## Related issues

None provided.

## Type of change

Bug fix / build configuration.

## Changes

- Enable package-on-build for packable Visual Studio projects in Canary, Nightly, and Release configurations and their Lite variants.
- Disable active-target-framework acceleration so packages include all configured target frameworks.
- Avoid duplicate channel suffixes on package IDs and preserve Canary/Nightly prerelease versions in Lite configurations.

## Affected packages & target frameworks

- All packable Extended Toolkit projects built with `Canary`, `CanaryLite`, `Nightly`, `NightlyLite`, `Release`, or `ReleaseLite`.

## Validation

- TestForm demo: Not applicable.
- Manual steps: In Visual Studio, select a package-producing configuration and build a packable Extended project; verify a full multi-target `.nupkg` is created under `Bin\NuGet Packages\<Configuration channel>`.
- Build command used: `dotnet pack "Source\Krypton Toolkit\Krypton.Toolkit.Suite.Extended.Outlook.Grid\Krypton.Toolkit.Suite.Extended.Outlook.Grid 2022.csproj" --configuration Canary --no-build -p:TFMs=all -p:BuildingInsideVisualStudio=false`
- Unit tests: Not applicable.
